# Схема проверенного решения

Каждая строка product list получает отдельный объект:

```json
{
  "source_row": 4,
  "product": "Abacavir & Lamivudine Tablets USP",
  "dosage": "600+300 mg / 300+150 mg",
  "packing": "30 tablets in jar",
  "segment": "ARV",
  "normalized_inn": "Абакавир + Ламивудин",
  "accepted_registry_inns": [
    "Абакавир+Ламивудин"
  ],
  "desired_form": "таблетки",
  "form_terms": [
    "таблет"
  ],
  "match_note": "Прямое совпадение двух компонентов.",
  "confidence": "Высокая",
  "decision_status": "matched"
}
```

## Поля

- `source_row`: строка исходного product list.
- `product`, `dosage`, `packing`, `segment`: исходные данные без смыслового изменения.
- `normalized_inn`: понятное отображение для читателя отчёта.
- `accepted_registry_inns`: только точные сырые значения поля МНН ГРЛС, одобренные после проверки.
- `desired_form`: форма из product list для отдельного сравнения. Если форма в источнике отсутствует, оставьте пустую строку; тогда отчёт выделит количество всех лекарственных препаратов как основной доступный показатель.
- `form_terms`: короткие проверенные фрагменты русского текста формы, например `таблет`, `капсул`, `крем`, `суспенз`. Они не ограничивают общую INN-выборку. Если форма не указана, используйте пустой список.
- `match_note`: краткое объяснение решения и исключений.
- `confidence`: человекочитаемая оценка, например `Высокая`, `Средняя`, `Требует проверки`.
- `decision_status`: `matched`, `not_found` или `manual_review`.

Для `not_found` оставьте `accepted_registry_inns` пустым. Все РУ с одобренными точными значениями МНН автоматически берутся только из раздела `Действующий`; одинаковый номер РУ считается один раз.
